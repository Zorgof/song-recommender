# ADR-00: Step 0 — Repository scaffolding

- Status: Accepted — Python version amended by [ADR-00.1](step-00.1-python-3-14-and-dev-environment.md)
- Date: 2026-10-07
- Step: 0

## Context

Step 0 of the [implementation plan](../implementation-plan.md) sets up the monorepo
skeleton: a backend Python project, a frontend React + TypeScript project, quality
tooling, the documented environment template and a README stub. No product
functionality is part of this step.

## Decision / What was implemented

### Repository layout

```
.editorconfig            shared editor settings (LF, UTF-8, 2 spaces; 4 for Python)
.env.example             every configuration variable of the planned system, documented
.gitignore               extended for this project (see "Issues")
README.md                project overview, docs links, dev setup
backend/                 Python project managed by uv
frontend/                React + TypeScript project generated by create-vite
docs/adr/                ADR index, template and this ADR
```

### Backend (`backend/`)

- **uv** project (`uv 0.10.9`) with `package = false`. The code lives in the `app/` package and is not built as a distributable.
- **Python 3.13** is pinned by `.python-version` and `requires-python = ">=3.13,<3.14"`. uv installed a managed CPython 3.13.12; the system Python is 3.12.3 and is not used.
- No runtime dependencies yet. Dev dependencies, locked in `uv.lock`: pytest 9.1.1, pytest-asyncio 1.4.0 (`asyncio_mode = "auto"`), ruff 0.16.10, mypy 2.4.0.
- Tool configuration is in `pyproject.toml`:
  - ruff: line length 100, rule sets E, W, F, I, B, UP, SIM, ASYNC, RUF.
  - mypy: `strict = true` over `app` and `tests`.
  - pytest: `pythonpath = ["."]`, so tests import `app` directly.
- `app/__init__.py` exposes `__version__ = "0.1.0"`. One smoke test checks it, so that `pytest` has something to collect: an empty test run exits with code 5, which counts as a failure.

### Frontend (`frontend/`)

- Generated with `create-vite@9.2.1`, template `react-ts`: **React 19.2, TypeScript 6.0, Vite 8.3**, `@vitejs/plugin-react` 6.
- Node.js **24 LTS** is pinned in `.nvmrc` and `engines.node >= 24`. `package-lock.json` is committed.
- Template boilerplate removed: demo assets, `App.css` and the counter demo. `App.tsx` is a minimal placeholder; `index.css` holds base styles only.
- Package renamed to `song-recommender-frontend`, version `0.1.0`.
- Scripts: `dev`, `build` (`tsc -b && vite build`), `typecheck`, `lint` (oxlint), `format`, `format:check` (Prettier), `preview`.
- Prettier 3 with `.prettierrc.json` (no semicolons, single quotes, trailing commas, width 100) and `.prettierignore`.
- The Vite dev server proxies `/api` to `http://localhost:8000`, so the frontend can call the backend in development the same way it will through nginx in Docker.

### Configuration template (`.env.example`)

- Lists every variable needed by the planned steps: app, LLM keys, model tiers, STT, Spotify, YouTube, LangSmith (US endpoint) and the Docker port.
- Every comment sits on its own line, so the file parses the same way in Docker Compose `env_file` and in python-dotenv.
- `LLM_LIGHT`, `LLM_HEAVY` and `STT_MODEL` are **left empty on purpose** (see "Deviations").

## Deviations from the plan

| Plan | Actual | Reason |
|------|--------|--------|
| ESLint + Prettier | **oxlint** + Prettier | The current `create-vite` `react-ts` template ships oxlint (with React hooks rules) instead of ESLint. It is much faster and has no flat-config plugin wiring. The plan was updated to match. Type-aware rules (`oxlint-tsgolint`) can be added later if needed. |
| Default OpenAI model ids in `.env.example` | Empty `LLM_LIGHT`, `LLM_HEAVY`, `STT_MODEL` | The OpenAI model line-up changes often and the public information found was ambiguous. As the plan already says, the ids are verified against the OpenAI docs and filled in during step 2 (LLM) and step 6 (STT), together with startup validation that rejects empty values. |

## Issues encountered and how they were solved

1. **Node.js is not installed in the WSL distro.**
   A Node 24.21.0 LTS binary was downloaded from nodejs.org, checked against the official SHA-256 sum, and unpacked into a temporary session directory. It was used only to run `create-vite`, `npm install` and the checks. Nothing was installed system-wide.
   **Follow-up for the developer:** install Node 24 LTS locally (e.g. via `nvm`/`fnm`, using `frontend/.nvmrc`) for frontend work. From step 9 the frontend also builds inside Docker.
2. **Docker is not available inside WSL.** `docker` reports that the Docker Desktop WSL integration is not enabled. This is not needed for step 0.
   **Follow-up for the developer:** enable *Settings → Resources → WSL integration* for this distro in Docker Desktop before step 9.
3. **The Python `.gitignore` template ignored every `lib/` and `lib64/` directory.** That would have silently ignored future frontend code such as `frontend/src/lib/`. The patterns are now anchored to the repository root (`/lib/`, `/lib64/`), and this was checked with `git check-ignore`.
4. **`.gitignore` additions:** `data/` (SQLite runtime files) and `node_modules/`. `.env`, `.venv`, `dist/` were already covered by the root or the template `frontend/.gitignore`.
5. **pytest exits with code 5 when it collects no tests.** Solved with the smoke test described above.

## Consequences

- Step 1 can add runtime dependencies (`fastapi`, `pydantic-settings`, SQLAlchemy …) with `uv add` on top of a working lint, type-check and test setup.
- mypy runs in strict mode from day one, so every later module has to be fully typed.
- Frontend libraries planned for step 7 (TanStack Query, React Router, Tailwind CSS, react-i18next, Vitest) are **not** installed yet, to keep this step minimal.
- No Docker files exist yet; they arrive in step 9.
